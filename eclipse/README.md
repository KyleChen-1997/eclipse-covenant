# 星蚀契约：群星回响 · 浏览器试玩 V10

英文名 **Eclipse Covenant**，建议仓库名 `eclipse-covenant`。GitHub Pages 发布步骤见 [项目首页](../README.md)。

108 位角色、16 个主线区域 / 48 关、8 个装备秘境，包含召唤、同名卡升星、随机词条装备、五人编队、3D 自动战斗和批量扫荡。单机免费试玩，模型、图片、音效和 Three.js 均在本项目，无运行时 CDN 依赖。

## 打开

在上一层项目目录运行 `npm start`，访问 http://127.0.0.1:4180/ 。无需安装 npm 依赖。请使用本地 HTTP 地址，直接双击 HTML 无法加载三维模块。

初始拥有米洛、岚雀、绯织和 200 枚星契。新篇礼物为布兰、芙萝拉和 50 星契；曙光礼物为泰莎、卢恩、50 星契和 900 星尘。装备页另有一次性 600 星尘锻造补给。所有装备通过星铸秘境获得；已有旧版礼包装备保留。

1. 召唤收集角色，在图鉴查看技能和养成。
2. 编入最多五名不同角色，前排更容易承伤。
3. 进入星蚀远征推进主线，或进入星铸秘境获得装备。
4. 在星铸装备中穿戴、强化或升星。属性在下次出战时进入战斗快照。
5. 战斗全程自动。支持暂停、1× / 2× / 4×、跳过；跳过使用相同规则，不保证获胜。
6. 首通后可自定义扫荡 1～1,000,000 轮；快捷选项支持 10 / 100 / 1,000 / 1 万 / 10 万 / 100 万。

共 31 种装备，武器 / 护甲 / 圣物三个部位，N / R / SR / SSR / UR 各五件，SP / SSP 各三件。每件有独立生成的原画，星铸图录可查看全部设计。同件只能由一人穿戴，可卸下和转交。

| 秘境 | 建议等级 | 解锁 | N | R | SR | SSR | UR |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初火锻炉 | 1 | 初始 | 65% | 30% | 5% | 0 | 0 |
| 银月工坊 | 15 | 主线第 6 关 | 10% | 50% | 35% | 5% | 0 |
| 元素熔炉 | 30 | 主线第 12 关 | 0 | 15% | 55% | 28% | 2% |
| 星穹铸庭 | 45 | 主线第 18 关 | 0 | 0 | 30% | 58% | 12% |
| 神谕宝库 | 55 | 主线第 30 关 | 0 | 0 | 0 | 70% | 30% |
| 创世秘藏 | 60 | 主线第 42 关 | 0 | 0 | 0 | 40% | 60% |

每次秘境胜利随机一件，同档模板等概率；失败、撤退不掉装备。主线首通、重访、扫荡和礼包不再发放装备。秘境和主线通关记录分开，秘境不产星契。

- 每件装备独立抽取 2、3 或 4 条不重复副属性，条数等概率；类型为生命、攻击、生命百分比、攻击百分比、技能增幅、伤害减免。类型与数值随机，同名装备也不同。伤害减免合计上限 35%。
- 强化最高 +15：每次增加 6% 初始主属性，并随机提升一条副属性；不足四条时有 35% 概率新增未有属性。花费 `(稀有度索引+1) × (80 + 当前强化等级×45)` 星尘。
- 觉醒最高 5 星：每次增加 25% 初始主属性，同时随机提升 / 新增一条副属性。消耗一件同名、0 星、未强化、未穿戴的材料和星尘；基础费用 N / R / SR / SSR / UR / SP / SSP 为 30 / 60 / 120 / 240 / 480 / 1440 / 4320，乘以目标星级。
- 强化与觉醒倍率相乘。旧装备保留编号、穿戴和星级，首次加载补齐稳定的随机副属性，刷新不会重抽。
- 平加生命、攻击先合入角色数值，再乘百分比词条；技能增幅乘在成长倍率之后。战斗中更换或强化不会修改已经生成的战斗快照。

扫荡仅限已通关关卡，预览不产生奖励和随机数。主线每轮 3 星契、对应星尘和全队经验；秘境每轮一件随机词条装备、对应星尘和全队经验。同款装备在战报中合并数量，但库存中每一件独立，可逐件查看词条。扫荡与逐场胜利使用相同奖励规则与掉落分布，一次保存整批结算。超过 100 轮的秘境使用独立种子固定副属性，随机数流与逐场战斗的调用顺序不同。

## 音频与存档

第一次点击或按 Enter 后激活音频。顶栏音符或「声音设置 → 开启声音并试听召唤」可手动恢复。设置面板显示实际输出和素材加载状态；静音、音量与音乐偏好保存在存档。页面后台停止声音，回到页面尝试恢复。浏览器或系统本身静音时仍需用户解除静音。

正式存档键仍为 `eclipse-covenant-v1`。角色、经验、等级、同名卡、星级、装备、资源、保底与旧章节进度全部保留。进行中的战斗不保存；奖励与通关立即保存并防止重复领取。`/?qa=1` 使用独立 QA 存档，验收不修改正式资源。

## 批量接入 UR 以上的视频立绘

目前西里乌斯与维蕾雅拥有用户提供的实际视频；其余 17 位仍使用原有动态图片。视频制作方案、逐人动作与完整提示词见 `qa/portrait-video-plan.html` 和 `assets/videos/production-plan.json`。该清单不是已生成的视频。

将审核通过的 MP4（推荐 H.264、yuv420p、faststart）或 WebM 放到 `assets/videos/<角色 id>.mp4` / `.webm`，同一角色只保留一种格式。运行 `npm run portraits:import` 后刷新页面。`npm run build` 也会自动生成映射；缺失的视频不会被注册。西里乌斯继续兼容 `hero1.mp4`，若有 `sirius.mp4` 则优先使用新命名文件。

导入仅校验文件存在、体积和容器标头，仍需人工检查面部、手部、循环接缝与浏览器播放。每位角色需要独立参考立绘，建议先做 1 位 UR 和 1 位 SSP 试片再批量生成。
